# Math Game

A math learning game for kids ages 5-15: flashcards, speed drills, rewards and two-device multiplayer.
Built with Expo, React Native and TypeScript for Android, with a web build for PC.

The full plan lives in [docs/build-plan.md](docs/build-plan.md).

## Running it

```bash
npm install
npm run web        # open in a browser on this computer
npm test           # unit tests
npm run typecheck
```

On Android, everything except playing nearby runs in Expo Go (`npm start`, then scan the QR code).
Playing nearby uses our own native module (`modules/math-nearby`), so it needs a real app build.

## Building the Android app (APK)

**Easiest: let GitHub build it.** Every merge to `main` runs the "Android APK" workflow, which posts
the app on the [Latest Android app](../../releases/tag/latest-apk) release. On each phone, open that page
(signed in to GitHub, since the repo is private), tap `math-game.apk`, and allow installing from the
browser when asked. To build without merging, open the Actions tab → Android APK → Run workflow.

**Updating.** Each build is stamped with its workflow run number, and the release also carries a
`version.json` with that number. On launch the app reads it, and when a newer build is out, Home shows
an "Update now" button that downloads the APK and opens Android's installer (Settings → Check for
updates does the same). This needs the release to be downloadable without signing in, so the repo has
to be public.

**Over-the-air updates.** When a merge only changes JavaScript (screens, questions, rewards, fixes),
the workflow skips the APK and publishes it with EAS Update instead, which takes a few minutes. Phones
download it by themselves at launch and Home shows "Restart to get it". The workflow tells the two apart
by the native fingerprint stored in `version.json`. This needs an `EXPO_TOKEN` secret (an Expo access
token) under Settings → Secrets and variables → Actions; without it every merge builds an APK as before.

The other two ways also give an `.apk` to install on each phone.

**In the cloud with EAS (no Android Studio needed):**

```bash
npx eas-cli@latest login          # free Expo account
npx eas-cli@latest build -p android --profile preview
```

When it finishes, open the link it prints on each phone, or scan the QR code, to download the APK.

**On your own computer with Android Studio:**

```bash
npx expo run:android --variant release    # with a phone plugged in over USB
```

The `android/` folder is generated by `npx expo prebuild` and isn't committed.

## Testing Nearby on two phones

1. Install the APK on both Android phones. Turn on Bluetooth and Wi-Fi on both.
2. On each phone: Settings → 📡 Play nearby (test) → Allow.
3. Tap **Try the Nearby test**. On phone A tap **Host**. On phone B tap **Find**, then tap phone A's name.
4. Both phones show "Connected" and the same 4-digit code. Tap **Send hello** on either phone and the
   message shows up on the other one.

Emulators can't do this; it needs two real phones.

## Layout

```
src/app         routes (Expo Router); each file just renders a screen
src/screens     Home, Profiles, ModePicker, Play (round + results), Progress, Shop, Settings,
                Parent, Permissions, NearbyTest
src/components  BigButton, OptionGroup, ChoiceButtons, NumberPad, FlashCard, TimerBar,
                StreakCalendar, CompanionBubble, Screen
src/constants   theme, difficulty configs, shop catalog, badges
src/store       Zustand stores persisted to AsyncStorage
src/utils       mathEngine, gameSession, scoring, adaptive, rewards, progress, dates,
                shop, badges, weekly, soundEffects, seededRandom (+ tests in __tests__)
src/test        shared test fixtures
src/types       shared types
src/hooks       useTimer, useGameSession
src/services    multiplayer transports (Phases 8-9)
modules/math-nearby  native Android module wrapping Google Nearby Connections, and its
                config plugin that adds the Bluetooth / Wi-Fi permissions
```
